# 📋 MySQL Database Sanitizer - Итоговое предложение

## ✨ Что мы сделали

### **Упрощённый workflow** (именно как вы хотели):

```bash
# 1. Создайте дамп базы данных
mysqldump -h production.db.internal -u root -p > dump.sql

# 2. Отдайте ему в Docker контейнер
cd /project-data-sanitizer
./start.sh    # ← Одна команда!

# 3. Готово!
ls ./output/
# sanitized.sql.gz ← анонимизированная база готова к загрузке
```

## 💡 Ключевые особенности

### 1️⃣ **Простота использования**
| До | После |
|----|-------|
| Настройка нескольких сервисов | Один `docker compose run` |
| multiple configs, env vars | Один `.env.example` |
| Нужно знать команды Greenmask | Простой `./start.sh` скрипт |

### 2️⃣ **Экономия на LLM**
```
Qwen3.5 Flash vs MiniMax M2.5:

Qwen3.5 Flash:   $0.10 / 1M tokens prompt
                 $0.40 / 1M tokens completion

MiniMax M2.5:    $0.30 / 1M tokens prompt  ⬆️ 3× дороже!
                 $1.20 / 1M tokens completion  ⬆️ 3× дороже!
```

### 3️⃣ **Сохранение целостности БД**
- ✅ Primary Keys не меняются — внешние связи intact
- ✅ Foreign Keys работают автоматически (без ручного обновления)
- ✅ Consistent masking — "Иван Иванов" везде становится одним именем
- ✅ Optional mapping JSON — можно восстановить связь при необходимости

### 4️⃣ **Гибкость настройки**
- YAML конфиг без кода
- Шаблон промптов для каждого типа полей
- Легко добавить новые правила трансформации
- Поддержка кастомных Python трансформеров

## 🔑 Ответы на ваши вопросы

> **"Как мы это будем передавать?"**

**dump.sql** файл через Docker volume mount:
```bash
docker compose run --rm \
  -v $(pwd)/dump.sql:/input/dump.sql \
  greenmask
```

> **"Можем опубликовать образ контейнера где есть база готовая?"**

Да, но я предлагаю **более простой подход**:
- Образ содержит только **Greenmask + transformers** (~50MB)
- База передаётся как внешний dump.sql файл
- Контейнер сам обрабатывает и выдаёт результат

Если очень нужен full-image с предзаполненной базой — могу доделать, но это увеличит размер образа до ~500MB.

> **"Будем сохранять мэппинг или будем просто показывать связность через ключи?"**

**Оба варианта поддерживаются:**
1. По умолчанию: маппинг НЕ сохраняется (меньше токенов, быстрее)
2. Опционально: сохраняем в `mapping.json` для обратной совместимости
3. Primary Keys не меняются — логическая связность всегда работает

> **"Какой план?"**

См. раздел **Next Steps** выше. Основная цель: **создать рабочий прототип за 2-3 дня, затем оптимизировать.**
